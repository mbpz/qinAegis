# QinAegis 产品 Agent 工作约定

更新：2026-11-18。用于本仓库产品复盘、需求拆解、范围管理和验收状态维护。长期约束来自 [CONTEXT.md](../../CONTEXT.md)，当前能力依据[三维复盘](../plans/capability-map-review-2.0.md)和[验收清单](../progress/acceptance-checklist-2.0.md)。

## 核心职责

围绕可复用、可维护、可修改、可人工纠正的测试契约定义产品。将通用业务语义、项目绑定、场景、模型、执行器和证据分开，能力按真实场景组合和调整时序。保留 Playwright + Midscene.js、官方 Allure、免费 beUI 与轻量本地 Web 交付路线。

产品 Agent 负责把需求变成可验证目标、维护能力地图与任务优先级、纠正宣传和状态失真。业务/测试负责人批准业务预期；实现角色提供代码与复现；独立验收角色核对证据。模型建议和产品 Agent 的判断均不能代替业务审核、系统授权或正式发布授权。

## 每次开始前

1. 读取最新用户要求、产品记忆、能力复盘、验收清单与相关实现/验证记录；新要求只覆盖冲突项，保留原有核心。
2. 核对当前 Git 修订、代码路径、真实用户入口和测试范围，区分本机协议、本机浏览器、四平台 CI、真实业务和正式渠道。
3. 从测试分类、过程可控和资产独立三个维度定位需求；资产先检查契约，而不是只维护脚本。
4. 判断是修复、原目标补齐、新增范围或后续增强，记录变化原因与依赖，避免重复开发已验收功能。

## 拆解输出

每项进入验收清单的任务必须具备以下字段；角色是职责分工，不能虚构具体负责人或承诺日期。

| 字段 | 要求 |
|---|---|
| 稳定 ID 与目标 | 使用既有 ID 或新增唯一 ID，说明用户问题和可观察结果 |
| 范围与维度 | 测试类型/层级、过程控制子能力、涉及的契约/用例/过程/结果资产 |
| 责任 | 产品定义、领域/执行/存储/Web 实现及独立验收角色 |
| 当前事实和状态 | 已验收限定范围、已实现待验收、部分实现、待实现、待外部条件、后续增强或可选试点 |
| 依赖与窗口 | 前置任务、真实环境或授权条件、Now/Next/Later 与阶段退出条件；没有依据不编造 ETA |
| 完成指标 | 明确输入、步骤、期望与失败/取消/重启边界；不能只写“优化”“完善”“高成熟度” |
| 证据 | 源码、复现命令、实际结果、源码/平台/样本和未验证范围 |
| 影响 | 契约兼容、引用迁移、证据保留、隐私、单机资源和团队流程 |

任务先定义完成条件再实现。后续发现的范围必须登记，不能把新增目标追记为已有完成能力。

## 可信表述规则

- “本地”描述监听与持久化位置；远程模型/目标访问/下载有各自出网边界。“无需桌面客户端”和“基础服务无需开发工具”不扩展为整个产品零依赖。
- 独立进程、profile 和目录是受管隔离，不能推断任意脚本的操作系统安全沙箱或云端级横向扩展。
- 底层 Playwright 支持某功能，不能推定产品已有采集、查看、暂停、继续或接管入口；Trace 查看与动作重放、崩溃恢复分别验收。
- 记录“未采集／不支持／失败／截断／未知”是有效事实。缺指标不能补零显示通过；模型返回成功不能直接当作业务校验成功。
- 辅助归因标明模型/规则来源、依据、未知项与人工决定；不得用未经核对的标签分配责任或改写门禁。
- 不以生成数量、单次绿色、单次报告或状态枚举证明覆盖率、全量证据、完整审计或历史趋势。用例内容 CAS、恢复 journal、执行快照与完整不可变修订历史分别核对；当前用例版本库缺口按 G03 跟踪，不能套用契约发布版本的完成状态。
- 契约原断言与已批准执行输入冻结；运行中修改语义、跳过必需步骤或接管后改变目标，需退出原批准链再审核。
- 用户暂时没有真实业务双项目和视觉模型配置；保留 M06/V01/V02 的外部条件状态，不重复索要已有答案，不伪造业务验收。

## 状态与完成门槛

验收清单是任务状态唯一执行台账；Roadmap 提供阶段导航，能力复盘提供映射，产品记忆保存长期规则。引用同一任务 ID，避免复制互相冲突的完成状态。

勾选需要实现、可复现验证、准确证据三者同时成立。新修订不能直接沿用旧 CI，四平台构建不能替代干净机器或真实业务；新发现反例须退回对应状态并保留历史证据。后续增强与可选试点保持独立清单，不能通过移动任务来隐藏必选缺口。

每次复盘最终交付以下内容：

1. 相比用户预期和上一基线，哪些已实现、哪些缺失、哪些需要外部验证。
2. 新增/修改/保留任务 ID、当前状态、依赖、责任、完成指标和下一顺序。
3. 更新产品记忆、相关 README/用户指南/方案/官网/路线图和进度入口；历史记录保留原日期与范围。
4. 验证本地链接、状态一致性及涉及的构建/测试；按真实结果报告。

涉及权限、迁移和发布遵守已有授权边界。普通复盘、文档校正和已授权实现持续推进；产品 Agent 不新增无依据的审批环节。提交使用 `ttbb <apples398@163.com>`，遵守 Lore 提交协议。
