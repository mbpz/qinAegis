# G01 / G03 资产审计与修订存储方案

2026-11-19。领域实现计划，尚不代表整体验收完成。

用例沿用项目级 `.transition.json` 独占事务锁；新增私有 `.history/<case>.json` 保存按序完整 JSON 快照和审计记录（状态变更也建修订），父修订必须连续，删除为显式空快照。现有资产首次接入仅记录当前快照，作者/过去历史标记 unknown，绝不推断已丢失历史。新增/typed-save/编辑/状态变化/删除均先持久化同一恢复 journal，再写历史和当前文件，最后清 journal；历史写入幂等以完整前后快照、父修订和内容摘要核验。恢复期间查询必须先完成 journal，因此不暴露历史领先于当前资产的中间状态。存储写入失败保留恢复意图，CAS失败不生成事件。历史文件有总量上限，满时拒绝变更，不裁剪旧修订。

每条修订包含完整快照、revision/parent_revision、内容精确 digest、来源、已知作者或 unknown、原因和操作。历史查询与运行冻结返回同一已锁定资产快照的确切修订；旧版本恢复只通过当前 digest CAS创建新 Draft，移除 provenance，保留完整历史，不继承历史批准。

契约库在同一个现有私有原子 JSON 内增加 audit 字段；每个 CAS mutation 与事件同写，记录变更前后修订及完整受影响集合（排除 audit 自身防递归）。旧库无审计时明确历史未知。审计上下文来自显式调用方；未提供时 unknown，不能凭本机登录名冒充业务作者。容量耗尽整体拒绝变更。

验收：真实文件CAS与并发冲突无事件；每个journal崩溃边界恢复幂等；历史篡改/链断裂拒绝；legacy未知；删除有墓碑；历史恢复新Draft/无provenance；原有编辑/审核/状态存储回归。Web/运行记录集成由父任务实现，独立验证。
