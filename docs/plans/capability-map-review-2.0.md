## 1. 产品结论与衡量方式

产品帮助测试人员把经审核的业务预期积累为可复用契约，在不同项目绑定下执行，并保留能够核对的输入、动作结果与证据。轻量本地 Web、可切换模型、执行器和 Allure 为这一闭环服务。AI 生成速度、卡片数量和单次跑通不能单独证明这一价值。

本次拆解保留三个观察维度：测试分类、过程可控、资产独立。资产维度首先补入可复用契约，随后才是用例、过程和结果。六张功能卡片作为能力分组使用；当前官网已经采用契约核心与模块化执行布局，不能将这六组视为当前页面的六项已验收功能。

| 产品目标 | 当前基线 | 成功条件及观察窗口 |
|---|---|---|
| 契约复用有效 | 双本机项目协议闭环；真实业务未验收 | V01/V02：两个授权项目固定同一发布契约，核对各自绑定、原断言、截图和 Allure；每次契约迁移复测受影响引用 |
| 运行依据可靠 | 固定来源、结果及已有截图；完整过程采集不足 | E01–E03：受控成功/失败/取消/中断每类场景均能解释证据是否采集、是否完整、与哪次运行关联；发布前验收 |
| 模型建议可治理 | 人工/模型待审纠正、完整依据、人工审核与新版运行观测已接入；真实业务另验 | M03/M07/G02：每项建议有依据和人工决定，不自动放宽原断言；真实样本不足时明确样本不足 |
| 安装和操作成本可控 | 基础 Rust 服务内嵌 Web；独立运行时按需安装 | R/I：逐平台干净安装、启动、升级/回滚及资源实测；每个发布候选复核 |
| 人机协同可控 | 只有进度、排队、取消和中断查看 | H01–H03：按阶段先实现安全暂停，再同会话继续，最后受限接管；每阶段单独验收，不自动推定崩溃可续跑 |

没有真实用户覆盖率、模型分类准确率、效率提升比例或真实业务复用率的测量值，暂不填写推测百分比和“成熟度高”评分。

## 2. 状态口径

状态描述同时带范围与证据。代码存在、协议 fixture、本机浏览器、四平台 CI、真实业务及正式渠道分别记录。

| 状态 | 使用条件 |
|---|---|
| 已验收（限定范围） | 范围内实现、复现及证据齐全；只勾选该范围 |
| 已实现待验收 | 实现存在，缺对应平台或真实场景证明 |
| 部分实现 | 只完成目标中的一部分，列出已做与缺口，保持未勾选 |
| 待实现 | 当前用户路径没有可用实现，底层库支持不计完成 |
| 待外部条件 | 明确缺少授权项目、模型、干净系统、证书或渠道授权；其他工作继续 |
| 后续增强／可选试点 | 明确进入后续阶段或单独试点，仍保留未完成状态 |

任务因证据不足退回待验收；发现实现缺失退回部分实现或待实现。历史成功证据保留原范围与源码，不覆盖新结论。I07 的 RC 复核需明确本轮支持范围、追加基础能力和后续增强，不能通过移走缺口宣布整体完成。

## 3. 维度一：测试分类与传统方式对照

以下差异为当前架构与工作方式的比较，不是对所有传统工具的优劣排名。

| 子能力 | 当前实现／状态 | 与常见脚本工作方式的差异 | 边界及关联任务 |
|---|---|---|---|
| UI / E2E | Playwright + Midscene.js 视觉动作、断言、抽取适配已接入；真实双项目待验收 | 业务契约与具体页面动作分离；视觉语义可减少部分定位器维护 | 不承诺完全消除定位器；Canvas/WebGL/Shadow DOM、缩放及动态页面需逐场景实测。M06/V01/V02 |
| 单元／组件／纯 API 测试 | 无对应完整产品执行路径 | 契约模型可表达复用目标，适配器仍需单独实现 | Rust/Node 的产品自身单元测试不等于产品支持用户单元测试；不补写已覆盖状态 |
| 冒烟／功能 | Web 分类与执行入口已接入；真实业务仍待验收 | 从需求/规格生成待审用例，保留原始契约与绑定，人工批准后执行 | 文本生成不是每次都先视觉理解页面；模型生成数量不代表需求覆盖率。F06/G02/V01 |
| 性能 | Lighthouse CLI 调用、真实指标解析与明确失败已接入，真实场景待验收 | 统一关联运行与结果文件，保留工具实际指标 | 需另装工具；不能把普通用例 duration_ms 当成页面性能指标。F07 |
| 压测 | Locust CLI、聚合 CSV 校验已接入，真实场景待验收 | 统一关联运行、负载参数与门禁结果 | 当前参数为 10 users、spawn rate 2、30s；不是任意规模并发产品。负载能力和被测容量分别衡量。F07/I04 |
| 安全／可访问性／兼容性测试 | 无完整已验收测试产品能力；ZAP 明确不可用 | 可通过未来能力适配扩展 | 工作台自身键盘检查与 I06 浏览器兼容不等于被测产品的无障碍/跨浏览器测试矩阵 |
| AI 生成与人工维护 | Draft/Reviewed/Approved、编辑失效、差异和重新审核已有本机闭环 | 生成建议进入资产治理，避免模型输出直接成为可信预期 | 视觉幻觉、弱断言和遗漏业务规则仍需人工把关；不能自动修复原始业务语义。M03/G01–G03 |
| 执行环境 | 独立 Chromium context/profile、受管进程与工作目录；全局单执行槽 | 本机可诊断、取消并保留独立证据，部署形态轻量 | 进程/profile 隔离不是操作系统安全沙箱；不支持集群或多项目大规模并行。T06 |

“四类统一门禁”应表述为统一结果和门禁接口已接入；某类引擎未安装、未运行、指标缺失、取消或清理失败时不得显示通过。Lighthouse 与 Locust 的实际负载和指标不由 Playwright 自动提供。

源码入口：`sandbox/src/yaml_runner.ts`、`sandbox/src/lighthouse_runner.ts`、`sandbox/src/locust_runner.ts`、`crates/web_client/src/app.rs`、`crates/core/src/service/test_case.rs`。

| 辅助归因 | Web 运行链待实现 | 当前知识模块存在关键词启发式，不是已接入的模型根因分析 | M07：原始事实与建议分开，区分产品/测试/环境/模型/未知，人工复核与纠正 |

当前 `yaml_runner.ts` 与 `capture.ts` 按冻结策略采集 PNG、console、network 有限元数据、步骤及官方 Trace，`executor.ts` 负责受管 context 与附件交接；收据标识缺失/失败/截断/未知。`crates/core/src/capture.rs` 安全迁移附件并控制最终配额；临时峰值仍有单次 queued write 边界。采集步骤事实与 Allure 逐动作展示是不同能力，不能把已有附件推定为完整 Allure 动作树。`knowledge.rs` 的启发式分类不能据其存在就宣传 Web 自动根因分析。任务控制见 `app.rs::stop_job` 与 `jobs.rs` 重启恢复；目前没有 pause/resume/handoff API。

过程控制按以下顺序设计：先把正在发生与未采集的事实说清楚，再引入安全暂停点，再验证同会话继续，最后扩展受控接管。浏览器句柄、进程存活或 trace 文件都不能单独证明可安全恢复。

## 5. 维度三：资产独立与治理

| 资产 | 当前基础 | 缺口及风险 | 完成条件 |
|---|---|---|---|
| 可复用契约（核心） | 独立库、不可变发布、绑定、人工纠正、派生/弃用及选定迁移 | 同一业务语义在真实项目中是否适用仍待验证；模型来源与新版观测不等于语义证明 | V01/V02/M03：复用原断言，显式处理差异，旧运行依据仍可还原 |
| 测试用例 | G01/G03 本机完整快照/父修订/审计/对比/恢复 Draft/运行冻结已通过 | 最终全套及本修订 CI 待汇总；旧历史未知，本机会话标签不等于认证自然人；量化覆盖率仍缺 | G02：覆盖率分母来自已确认需求；恢复清 provenance 且不继承批准，模型建议不能自批 |
| 执行过程 | 冻结策略、收据、受管 PNG/console/network 有限元数据/steps/官方 Trace 与隔离查看 | E02 故障矩阵和临时磁盘峰值仍有缺口；日志、模型尝试及附件是不同事实源 | 保留完整/缺失/截断/未知状态；不将有限元数据或完整附件等同于无损全量事实 |
| 执行结果 | 独立 run.json、结构化结果、门禁与单次 Allure | 没有完整跨次趋势；失败归因未产品化；历史附件丢失需可诊断 | M07/E04/F08：建议不覆盖事实，清理保留引用与结果，趋势只使用真实观测 |
| 整体数据 | 默认本机目录，可用 QINAEGIS_DATA_DIR 隔离；配置备份/恢复 | 项目完整一致性备份、可迁移校验、保留策略尚未完成 | E04：在明确停止/快照边界导出，恢复演练、版本/摘要校验及失败保留原数据 |

本地持久化不等于数据绝不出机器。使用远程模型、访问被测站点和下载引擎均可能出网；模型选择需数据授权。基础服务无需全局 Node/Python，视觉运行时包含 Node 和测试依赖，浏览器另行准备；Lighthouse/Locust 还有各自依赖。“零客户端打包”和“基础服务无需开发工具”可保留，“整个产品零运行依赖”需删除。

复制目录只能视为受控备份候选：活动写入、配置目录、凭据引用、引擎和平台差异都需处理，不能宣传任意复制即完整迁移。进程隔离也不能证明任意脚本具备安全隔离。

### 当前存储方案核对

当前路径使用 Rust 管理本地文件，没有接入 SQLite/PostgreSQL。默认根目录为 `~/.qinAegis/`，可通过绝对路径 `QINAEGIS_DATA_DIR` 切换。结构化资产主要用 JSON，项目配置为 YAML、规格为 Markdown；截图及 Allure 附件为独立文件。受管资产通过 `AssetFile` 做进程间锁、有界读写、临时文件同步和替换；用例跨状态目录变更另外使用可恢复 `.transition.json`，成功后清为 `null`。journal 本身不是长期事件日志；独立用例历史与契约 audit 才保存对应变更，仍不是跨全部资产的数据库事务。

| 对象 | 当前落盘位置（相对根目录） | 已有保障与缺口 |
|---|---|---|
| 契约及发布版本 | `contracts/library.json` | 显式草稿/不可变发布及修订 CAS；audit 与内容同次原子提交，含审计总计 8 MiB 满额拒绝新变更，不清历史；旧事件未知 |
| 测试用例当前内容 | `projects/<project>/cases/<status>/<case>.json` | YAML 脚本嵌入 JSON；内容 digest CAS 防覆盖，与独立历史 revision 分开；修改后回 Draft |
| 用例版本迭代 | `projects/<project>/cases/.history/<case>.json` | 完整不可变快照、父修订、原因/来源/审核状态，恢复 journal 关联提交；每例 16 MiB 满额拒绝新变更。存量仅单条未知 legacy baseline；旧版恢复新 Draft、清 provenance、不继承批准 |
| 任务过程 | `jobs/history.json` | 最近最多 100 条任务，单条输出保留最后 64 KiB，结果/快照字段各 32 KiB；有截断标记，不是永久全量日志 |
| 场景过程 | `flow-executions/runs/<flow-run>.json` | 冻结计划、步骤检查点及关联用例运行；活动中更新，终态保护；不等于完整浏览器动作 Trace |
| 测试结果 | `projects/<project>/reports/<run>/run.json` | 冻结确切 case_revision、脚本、来源、目标、模型及实际结果；先 running 再写一次终态，终态不随用例编辑变化 |
| 报告与附件 | 同运行目录的 `evidence/<case>/`、`allure-results/`、`allure-report/index.html` | 受管 PNG/console/network 有限元数据/steps/官方 Trace 有收据与摘要；官方查看器按需隔离启动；报告不是结果事实源，不能推定全量或无损采集 |

当前选择符合轻量单机部署。G01/G03 本机核心/HTTP/UI 已通过，最终工作区全套及本修订 CI 待汇总；全量查询、容量扩展、跨资产一致性和 E04 备份恢复仍待独立设计，不新增数据库依赖。审计中的 local-owner 仅是本机会话标签；生成明确记 model_generation、作者为空，旧数据未知，不伪造认证身份。源码依据为 `storage/local.rs`、`storage/local/case_assets.rs`、`execution_records.rs`、`jobs.rs`、`flow_execution/store.rs` 和 `asset_file.rs`。

## 8. 团队流程与约束

- 测试/业务负责人维护契约语义、需求范围和人工批准。AI 提建议，产品 Agent 校核范围与证据，执行器返回观测，门禁按固定契约判定。
- 开发负责适配器与可观测边界；修复定位/等待与业务预期修订分开评审。提交后用新的用例/契约版本复测，保留旧失败。
- QA 设计成功、断言失败、模型失败、环境失败、取消、资源耗尽与强杀样本；协议 fixture 和真实业务验证分别留证。管理者查看覆盖范围、未知项和阻断原因，不能把 AI 归因直接作为责任分派。
- 审查输入包括契约/绑定/规格/执行计划/模型/采集策略。运行中冻结；接管或修改导致语义改变时终止原批准链，生成新修订或新运行。
- 成本和隐私以明确策略控制：单机容量、证据配额、保留期限、模型数据接收方、导出范围；配额耗尽及采集失败必须有状态，不能静默丢弃后宣称完整。
- 产品 Agent 每次迭代产出：目标变化、事实变化、任务状态差异、证据位置、剩余条件与下一顺序；历史用例状态不是统一审计，单次 Allure 不是跨次趋势，Trace 查看不是动作重放。
