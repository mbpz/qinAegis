# 2.0 契约执行追溯与生命周期验收

日期：2026-11-16。继续已批准的 2.0 方案，先推进开发进度中的第 1 项；后续模型、运行时、任务可靠性依赖本阶段结果逐项验收。

## 实现顺序

1. 保存用例的生成来源：完整契约版本/绑定/原断言快照、脱敏模型配置和原始脚本。旧用例没有来源时明确标记，不能补绑当前契约伪造历史。
2. 执行前固定已审核用例、目标 URL 与生成来源，保存唯一运行记录。执行后的结果、失败和必要证据关联同一记录；变更绑定/模型/用例不改写历史。
3. 增加版本弃用、新身份派生和经人工确认的批量绑定迁移；CAS、完整类型校验和原子提交，历史发布和运行记录保留。
4. Web 展示来源与运行记录，允许本机用户明确下载含项目数据的证据。沿用 beUI 免费组件，禁止默认导出秘密或自动迁移。
5. 验证真实 HTTP 服务、两项目和重启后历史读取，覆盖失败、空用例、修改脚本、旧资产、弃用及迁移拒绝。确定性执行器仅证明通信/存储闭环，不计为真实视觉模型验收。
6. 2026-11-16 用户追加并授权 Allure：终态运行导出标准结果，执行运行时固定官方 `allure@3.33.0`，Web 显式生成、查看与下载离线单文件报告。保留真实来源/附件和执行异常，报告与执行状态独立；验证实际官方生成器、重启读取、缺失运行时和浏览器隔离。

## 验收与边界

- 用例/运行/契约持久化复用私有原子资产机制；除用户追加授权的官方 Allure 及其锁定传递依赖外，不新增框架。执行事实写入失败必须使任务失败；报告导出/渲染失败单独报告，不篡改执行事实或门禁。
- 来源记录证明实际提供给生成器的输入，不证明模型生成脚本已实现全部业务断言；后者保留人工审核及真实业务执行验收。
- 执行结果逐用例保存并核对身份，不接受空批次成功。运行失败和业务断言失败区分，取消记录真实状态。
- 弃用禁止新的绑定与生成；已固定的历史输入仍可读取。迁移不自动改变已生成用例，需重新生成并人工审核。
- 契约生命周期记录保留本机库中；当前交换包只包含发布资产，不携带弃用/派生/迁移历史。用例状态移动跨两个文件位置，崩溃恢复仍归后续可靠性阶段，不能声称跨路径事务已经实现。
- Allure 不虚构步骤和逐用例起止时间，已有耗时保留在结果附件。标准结果可被其他兼容工具消费；当前 UI 展示单次运行，不承诺跨次聚合趋势。
- 真实 Playwright + Midscene 双项目业务执行必须具备可用引擎与经授权的兼容视觉模型，缺失时明确记录阻塞条件，不能用模拟输出替代。
- 运行时交付、持久任务恢复、跨平台安装及无障碍仍按原方案后续实施，不在本阶段声明完成。
