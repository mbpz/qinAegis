# 2.0 自动打包与官网迭代

日期：2026-11-16。用户要求继续 2.0 的 CI 自动打包与 GitHub Pages。完整 2.0 目标仍有真实业务视觉执行、引擎安装、任务可靠性及跨平台安装等验收缺口；本阶段不将它们标记为已完成。

## 本轮范围

1. PR、2.0 开发分支与主分支提交自动运行检查，构建本地 Web 服务归档，并保留可下载候选包；标签发布继续先生成草稿。
2. 统一 Cargo、Web UI、安装脚本与标签的产品版本。引擎包保留独立版本。拒绝版本不一致、无效标签、不完整归档或摘要。
3. macOS 双架构、Linux x86_64、Windows x86_64 产物均为服务程序和元数据；不恢复 `.app`、DMG、cask 或桌面客户端构建。
4. 官网改为 2.0 的本地 Web / 契约复用 / Playwright + Midscene.js / 模型路由 / Allure 产品说明，沿用免费 beUI。发布状态、引擎前提和未验收能力必须与产品记忆一致。
5. 官网独立构建，PR 产出预览文件，主分支部署 Pages；公开页面不携带本机配置、调用本机 RPC 或默认加入统计。页面相对资源路径兼容 `/qinAegis/` 项目站点。
6. 更新安装、CI 与产品进度说明。版本脚本只修改待审阅文件，不隐式提交、打标签或推送；Homebrew 仅跟随经过验证的正式稳定发布。

## 验证顺序

- 本地：版本/归档负测，工作流静态检查，官网及主 Web 构建，真实浏览器宽屏/窄屏与键盘操作，资源/链接和产品承诺检查。
- GitHub：推送 2.0 开发分支验证自动打包和预览构建，查看实际工作流结果；失败后修复并重新验证。候选包校验不等于干净机器功能验收。
- 发布边界：本轮准备可审阅分支及草稿 PR；不将开发版冒充 GA，不推送发布标签、不公开新 Release，不在未合并主分支时宣称线上官网已经更新。

## 完成证据

实际检查命令、产物与剩余限制记录在 [开发进度](../progress/local-web-2.0.md)；CI 行为与维护方式记录在 [CI/CD 集成](../CI_INTEGRATION.md)。
