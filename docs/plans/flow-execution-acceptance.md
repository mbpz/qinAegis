# 流程执行验收路径（F04/F05）

日期：2026-11-18。状态：schema 2 定义、受审快照、顺序内核、Web 执行接入已实现，本机核心/HTTP/实际浏览器及独立复核通过，四平台 CI 正在验证；F03 的 v1 发布及历史计划继续保持仅计划，不代表已运行。

## 执行契约与责任

第一条实际执行链从已审核用例开始，复用现有 `TestExecutor::run_case`、任务队列、受管进程取消/清理及官方 Allure。抽象的 `browser.observe`/`browser.interact` 不自动翻译成未经审核的 YAML，也不因新增运行入口变为已实现。模型负责建议，审核后的用例负责业务行为，执行器负责动作，事实库负责记录，报告负责展示；任一层不能放宽原始断言。

新增执行契约必须有明确 schema/能力版本，兼容历史 v1 描述符和 `executable=false` 计划。现有发布升级为执行版本需要重新校验、审核和准备；不能给旧计划补上“可执行”标记。草稿编辑、合法调序和运行预览应共用服务端类型、依赖、权限、副作用校验。

## 顺序与验收门槛

1. **版本化执行定义**：加入明确的已审核用例引用、类型化条件、显式等待、单步骤与总时限、重试及失败清理策略。条件仅接受有限比较和类型检查，不允许执行表达式；跳过及依赖跳过的行为必须确定。既有 v1 发布和计划可无损重载。
2. **执行准备**：固定用例全文、审核摘要、来源、目标、契约原始断言及参数，拒绝失效审核、错项目/目标、缺失关联和不支持能力。明确列出模型候选及端点、授权和注册修订；运行前配置不符时要求重新准备。凭据仅在内存中固定。
3. **逐步运行内核**：保存每次尝试的输入输出、状态、时序、实际模型、跳过原因与清理错误，输出通过类型检查才可流入下游。非幂等浏览器步骤仅允许一次尝试；断言失败、协议错误、取消不能笼统触发模型或动作重试。批准的备用模型仍需能力与数据授权校验。
4. **接入队列和取消**：复用全局执行槽，排队后不重新读取变化的资产。取消/超时传播到运行器；以单独有界预算完成失败清理，同时保留最初失败原因。受管进程真实退出、事实持久化后才释放执行槽；重启保留 interrupted，禁止自动重放副作用。
5. **Web 实际运行**：上述边界验证通过后才开放 Run；使用免费 beUI 组合、调序、审核和预览。用户可见当前步骤、尝试、取消/清理状态和历史固定快照，刷新后能恢复。缺运行时或实际 runner 的能力在提交前拒绝，并指向准备入口。

每步需核心回归、真实 HTTP 及适用的实际浏览器验收：类型/条件/跳过传播、等待取消、单步骤/总超时、有界重试、清理失败；资产修改后的排队快照、审核失效拒绝、真实受管协议进程退出、逐步事实与 Allure；最后验证 Web 运行、取消、刷新和历史。不以 fixture 通过替代两个真实业务项目视觉验收。

R03 原生维护的依赖授权不阻塞这条路径的内核和受管协议验证；缺少运行时时必须明确拒绝动作，不能据此宣称干净电脑已具备完整视觉能力。M06/V01/V02 仍等待用户提供已授权目标和本机模型配置。

## 已核对的接入边界

已实现独立 `schema_version: 2` 执行定义与受审用例快照。现有 `FlowDraft` 没有 schema 字段，v1 能力目录和 `FlowPlan` 的 `schema_version=1/executable=false` 必须保留原样；不能扩展旧目录后直接给历史计划开启执行。

首批操作只接明确等待及 `case.execute.v1`。用例引用包含受管项目、用例 ID、已批准完整内容修订及固定契约版本；复用现有 `InputSource`、`ValueType`、稳定依赖顺序和选定契约 `ExecutionSnapshot`。受审浏览器动作尝试次数固定为 1。有限条件和跳过语义不能执行表达式，也不修改已审核 YAML、契约断言或项目绑定。

准备时通过 `LocalStorage::get_case_asset` 的受锁读取核对 Approved 与精确内容修订，冻结脚本、目标、预期结果、来源和模型元信息；现有 `digest` 是完整内容修订，不是密码学摘要或授权令牌，不为此新增哈希依赖。凭据只留内存。Web Run 仅接新 schema 2 定义，缺前置条件拒绝准备；完整 F04 以本页验收证据为准。

运行内核需要给现有 `TestExecutor` 增加明确的取消并等待受管资源退出入口，复用所持 `MidsceneProcess::terminate`。正常 shutdown 的 RPC 响应成功与否不能作为取消清理是否完成的依据。请求超时和清理失败同时保留；等待实际退出后才允许推进下一步。

Web 复用统一队列，在入队前冻结资产及凭据。等待/跳过步骤不能塞入现有按用例结果覆盖校验的 `RunRecord`；流程执行事实独立版本化，已执行用例继续使用既有运行/Allure 证据。分步事实、取消清理与持久化验证通过后才接运行入口及免费 beUI 组合界面。


## 2026-11-18 内核验收证据与接入约束

核心 18 项回归覆盖类型/上游依赖/条件、稳定调序、等待与取消、单步骤和总时限、有界等待重试、跳过传播、历史来源契约全部匹配，以及 Approved 精确修订。真实受管协议子进程验证取消后孙进程端口释放和工作目录移除；这是协议清理证据，不替代模型或业务视觉验收。

尝试事实在保留前采用流式 JSON 字节计数，单个 TestResult 上限 128 KiB（包含转义开销）；失败结果同样限制，超限丢弃原文并失败清理。截图仅保存于尝试证据，数据流元信息不复制截图。运行和清理诊断分别限制 4 KiB，超限省略原文；清理超时必须报告未确认，未来应用层不能据此释放执行槽。受审用例禁止自动重试和 healing；等待仅在剩余总预算内重试。

初始内核事实可能含执行器错误、截图及业务内容；本批已在统一应用边界加入凭据脱敏、私有独立事实存储、冻结模型凭据与数据授权、实际运行/Allure 记录及队列清理门禁，再接 Web。调用者通过取消标志并等待内核结束；不能直接 abort future 后宣称清理完成。准备快照冻结项目目标，但不把已审核 YAML 自带目标覆盖视为网络目标隔离保证。


## schema 2 Web 接入与复核门槛

- `flow-executions/library.json` 保存草稿/不可变发布，最多各 64 项、32 MiB，整库修订 CAS；`runs` 最多 100 项独立私有事实。终态不可覆盖，记录必须符合冻结定义的稳定步骤顺序、尝试/类型/输出来源及清理时序。
