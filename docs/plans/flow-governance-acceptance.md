# 版本化流程与计划验收（F03）

日期：2026-11-18。接续已完成的 F01/F02，先实现无外部动作的流程治理；不新增依赖。

## 产品边界

可复用流程与项目配置分离。流程草稿声明步骤、依赖、类型化端口、输入来源、固定契约版本及模型角色。保存采用整库修订 CAS；发布必须校验已保存内容并明确人工确认，发布版本不可覆盖。允许调整独立步骤的声明顺序，依赖仍通过稳定拓扑排序约束。

输入来源仅允许字面量、流程输入或上游步骤输出，不接受可执行表达式。服务端能力描述符决定端口、所需权限、副作用和重试边界，客户端不能自行声明幂等来绕过保护。拒绝未知能力、缺失/重复/循环依赖、越界规模、输入缺失/类型不符、非上游输出引用及非幂等重复尝试。

项目计划固定发布流程、类型化实参、选定发布契约及对应项目绑定、原始断言和模型注册修订/脱敏配置。缺失绑定、版本不符、弃用契约、能力/凭据/远程数据授权不足明确拒绝。准备只做校验，不调用模型、浏览器或桌面，不授予执行权限。历史计划不随后续资产变化。

当前阶段的能力登记明确区分 planning_supported 与 runner_available。计划明确 executable=false；Web 显示仅计划，没有运行入口。实际条件、等待、超时、重试、失败清理及步骤模型降级属于 F04/F05/M04，不能用静态计划冒充执行完成。

## 实现顺序

1. 核心流程 DTO、受管有界私有资产库、草稿 CAS、校验、不可变发布；复用 Scenario、ValueType、AssetFile。
2. 项目计划准备和持久快照；复用契约/模型边界，严格冻结选定内容，不落盘密钥。
3. 严格 Web RPC 与免费 beUI 流程页面：编辑/保存/校验/人工发布/项目计划预览和历史查看。
4. 核心与真实 HTTP 回归、实际浏览器操作、独立复核、文档/产品记忆同步后勾选 F03。条件不齐保持未勾选。

## 验收

- CAS 冲突保留原草稿；过期/未保存内容不能发布；改动必须创建新版本，旧发布及计划可重载且不变。
- 类型、依赖、端口、规模、权限、能力、副作用和重试错误均在动作前拒绝。
- 同一流程可为两个本机测试项目准备不同绑定的计划，原始契约断言保持；这不替代两个真实业务项目视觉验收。
- 模型授权验证、计划/日志/导出无凭据；缺模型错误可恢复，修改注册不改变旧计划。
- Web 保存、校验、明确发布、准备和历史预览可实际操作，修改内容清确认，迟到响应不会混淆资产/项目。
- F04/F05/M04 和真实外部验收继续独立记录，不提前勾选。

## 验收记录

实际 Chromium 完成模板编辑、保存确认、已保存内容校验和不可变发布；同一发布为两个本机测试项目准备不同项目目标的计划，并查看历史原快照。修改实参/草稿清除确认，过期保存保留草稿，Reload 显式丢弃；保存响应被延迟后离开/重新进入页面，旧响应不覆盖新编辑器。控制台 0 errors/0 warnings。独立复核补齐项目目标及模型端点冻结后通过。核心与真实 HTTP 回归证明存储、类型、授权及历史边界，不代表真实业务或运行编排通过。v1 能力目录为既有计划验证契约；改变已有描述符前必须提供版本兼容，不得使历史计划失效。
