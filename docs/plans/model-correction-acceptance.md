# M03 模型纠正建议与人工验证闭环

日期：2026-11-18。范围为基于受管执行证据生成待审契约纠正建议，再关联新版本的实际运行观测。复用现有模型注册、correct 路由、队列、取消、契约存储与人工审核；不新增依赖。

## 输入和边界

- 入口只接收项目、契约/发布版本、受管 run/case ID、库修订及有界用户说明；服务端读取事实，不接受本机路径或客户端上传结果。模型必须显式配置 correct 路由，不能借用 generate 或偷偷切换视觉模型。
- 固定最新发布定义及库修订，核对终态 run 中选定 case 的项目、来源契约全文、绑定、原断言与目标。缺来源、活动运行、旧基线或身份不匹配拒绝。只发送选定用例必要摘要，不默认发送截图或整批报告。
- 用户说明、模型候选及批准的远程数据边界在派发时冻结。输入输出拒绝已知任务凭据回显；原文与解码 JSON 一并检查，错误不包含提供商正文。

## 目标行为

1. 模型返回完整 replacement、原因、局限与服务端证据 token。严格验证结构/尺寸/ID/下一版本、依据引用和原始发布兼容；模型不能发明路径或替代人工业务判断。
2. 每次实际尝试持久化 started/实际结果；只允许已批准备用链及可重试错误。检查点失败停止调用，取消检查覆盖请求前、返回后和提交前；重启 interrupted，不自动重放。
3. 模型来源、冻结输入、实际调用、原因/局限及证据与 Pending 提案一起原子保存。模型不能自批、自动发布、移动绑定或执行修复。来源不能只依赖有容量上限的任务历史。
4. 模型返回时仍使用提交前冻结的 expected_revision；冲突明确失败，不取最新修订自动重试。复用原有人工完整定义对照、approve/reject、最新基线及 CAS 校验。
5. 人工批准后继续显式迁移绑定、生成/维护并审核用例、执行新运行。另行关联受管新版本 run/case，严格核对新版来源和结果。旧 run 或模型建议不能充当新版本通过证据。
6. 观测只描述该冻结用例和环境的实际结果，保留原始失败。结构有效、来源有效、人工批准、实际运行观测分别显示；semantic_validation 保持 not_verified。

## 实现分工与验收

- core：有界 DTO、来源/观测校验、兼容旧格式的模型来源及不可变观测关联；契约存储继续私有锁/CAS/原子替换。
- Web：受管证据加载、correct 后台任务与持久检查点，结果查询/观测关联；维护任务与执行槽规则保持。
- UI：复用已有免费 beUI，明确选定证据、生成待审建议、查看完整新旧定义/模型来源/局限、人工审核以及新版本观测关联；切项目/输入修改后清除过期确认，迟到响应不污染当前选择。
- QA：真实隔离 HTTP 验证 pending→拒绝/批准→新版观测；跨项目/无来源/活动 run/旧版本/坏 token/坏输出/秘密转义/硬拒绝/批准备用/取消/重启和修订竞争。来源在任务淘汰后仍保留；旧 run 拒绝作为新版验证。补充相关核心、UI、构建、独立复核及真实浏览器验收。

本机实现与验收已完成，证据及重现命令见[验收清单](../progress/acceptance-checklist-2.0.md)；模型建议可能改变业务语义，只能交给业务负责人判断，不能把结构校验或测试绿色当作语义正确性证明。真实业务双项目与视觉兼容仍待用户环境。

复现：先构建 `cargo build -p qinAegis-web --bin qinaegis`，再执行 `python3 scripts/test-contract-correction.py /绝对路径/qinaegis`。脚本仅启动隔离数据根与本地模型/Node 协议夹具，不接入真实业务或模型。旧配置生成使用 `scripts/test-legacy-generation.py`；二者均进入四平台候选矩阵。
