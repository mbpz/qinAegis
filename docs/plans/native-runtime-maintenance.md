# 原生运行时导入与维护（R03/R05）

日期：2026-11-18。状态：依赖选择待明确授权；本文件是可审阅实现方案，不代表已实现。

## 最小依赖决策

项目规则要求“ No new dependencies without explicit request.”。基础服务目前没有可直接使用的 SHA-256、gzip 和 tar 库；现有 Python 导入器不能直接从运行中的 Web 服务调用，它持有服务实例锁且要求本机 Python。

建议给 core 添加 `sha2`、`tar`，并将锁文件已有的 `flate2 1.1.9` 声明为直接依赖，使用 Rust 解压后端。具体兼容版本在获准后通过 Cargo 解析、锁定和检查确认；不扩大默认服务运行时依赖。下载继续使用已声明的 reqwest，不新增 HTTP、数据库、客户端或打包框架。

这使安装后的基础服务可独立校验和解压，无需用户先装 Python、Node 或系统解压工具。拒绝自行实现密码摘要、tar 解析，也不把标记中记录的摘要当作当前文件已重新校验的证据。

## 实现顺序

1. **同一原生验证入口**：迁移现有 `scripts/install-runtime.py` 的拒绝规则；有界流式计算可信归档 SHA-256，逐条检查归档路径、重复项、类型、权限、链接、文件数、压缩包和展开总量、manifest/provenance、主机架构和逐文件摘要。先验证再执行捆绑 Node。
2. **受控传输**：新增独立有界上传端点，沿用会话/CSRF/Origin 验证，不把大归档塞进 1 MiB JSON RPC。下载只允许明确选择的可信发布来源及同来源清单，不接受任意 URL 或本地路径；摘要与来源先预览，用户明确确认。
3. **安装事务**：服务内共享运行时资源锁与现有任务队列；安装/升级/回滚与活动或排队引擎任务互斥。暂存目录和 current/previous 都固定在受管同卷目录；使用持久事务日志与可恢复 rename。任何校验、切换或健康检查失败均恢复旧运行时。
4. **升级与回滚**：展示当前/可回滚版本与来源；每次切换重新验证所选内容，确认时检查预览修订。没有可信来源或发现内容变化时拒绝激活；不能只凭 `.archive-sha256` 或入口可运行判为完整。
5. **Web**：Environment 使用现有免费 beUI，显示上传/下载/校验/暂存/切换/健康检查阶段，支持取消与真实失败；新运行时可用后再显式下载 Chromium。离线资产维护及既有报告查看始终可用。

## 验收要求

- 延续现有坏摘要、路径逃逸、内部/外部链接、硬链接、特殊文件、重复成员、超限、坏来源、错误主机和支持文件篡改测试；新增原生/旧导入器同一 fixture 的接受/拒绝一致性。
- 上传/下载取消、断流、无空间、锁冲突、队列互斥、各事务边界崩溃恢复、预览过期、健康检查失败后旧版本仍可运行。
- 在没有源码、全局 Node、Python 或开发工具的四平台环境，用捆绑 Node 实际启动浏览器及官方 Allure；每平台分别留证，不能用构建成功替代干净环境验收。
