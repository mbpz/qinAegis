# E01–E03 采集策略、过程证据与回溯验收

日期：2026-11-19。依次实现策略、受管采集和查看；通过后再推进 G01/G03 审计与用例修订历史。复用既有 Rust 私有原子资产、执行队列、Playwright/Midscene、官方 Allure 和免费 beUI，不新增依赖。真实双项目视觉验收继续待外部条件。

## E01：版本化策略

策略独立于业务契约和断言，以私有文件、修订 CAS 保存。新安装默认关闭可选诊断采集，仍保存结果、来源和任务事实；视觉执行所需屏幕输入不属于该开关。显式选择采集时说明截图、DOM、Trace 可能含业务敏感数据，不能承诺无损脱敏。模式包含关闭、仅失败、关键步骤、全量；当前引擎未实现的模式明确拒绝，不能静默降级。

普通执行在提交时冻结策略；流程在准备时固定策略并展示，后续修改只作用于新提交。RunRecord 与任务事实保留修订和完整策略；旧运行无策略时显示历史未知。执行前协商采集协议/能力，旧引擎不能确认支持时在浏览器动作前失败。

## E02：受管证据

按用例独立上下文采集截图、步骤、Console、Network 与 Playwright Trace。Console/Network 只采集有界允许元数据，不采请求/响应正文、认证头或 Cookie；Trace/截图另外明确敏感边界。单附件、整次运行最终保留附件及事件条数具有硬限额；Trace 暂存使用运行中目录监测并停止采集，但公开 Playwright API 不能阻止一次排队写入瞬时超额。该缺口保留，不能将 E02 整项标为通过。超额停止相应采集并记录截断，不改写业务断言。

引擎只返回收据和本实例私有目录内的固定普通附件。Rust 核验逻辑身份、类型、大小和摘要后私有原子落盘，再提交运行引用；无任意客户端路径入口。预计采集与实际状态分开：未请求、已采集、失败、截断、不支持、未知。取消、超时、强杀、收尾/持久化故障不推断完整；服务重启不重放动作。报告失败不覆盖原始测试结果，缺失或坏附件不伪装为已存在。

## E03：本地查看

工作台按运行/用例查看冻结策略、收据、步骤和日志元数据，下载只接受已提交收据引用并再次核对身份、大小、摘要及普通文件边界。历史未知、缺文件、篡改、截断与不兼容明确显示。

Trace 复用已锁定 Playwright 官方静态查看器，独立受管 loopback origin、短期随机凭证和固定 ZIP/静态资源映射；禁止直接暴露允许任意 path 的官方 show-trace 文件服务。查看过程不执行测试、不恢复浏览器、不重放副作用，不授予主工作台 API 权限。验证离线、关闭回收、资源访问限制和查看器版本边界。

## 验收顺序

1. 策略严格版本/字段/配额校验、CAS、确认重置、普通/排队/流程冻结、旧引擎拒绝、历史兼容。
2. 确定性协议 fixture 与真实本地 Chromium 分别验证成功/业务失败、截图/Trace 异常、事件/字节额度、取消/超时/强杀、收尾/磁盘失败、重启事实不变；fixture 不替代真实视觉模型。
3. 实际浏览器验证策略设置、任务/报告关联、步骤/日志查看、安全下载、缺失/篡改、离线官方 Trace 查看及关闭；现有 Allure 继续可用。
4. 核心/执行器/UI 回归、构建、Clippy、独立复核和四平台候选 CI；只按实际证据更新 E01/E02/E03。

实际实现与验收证据见验收清单。已核对锁定 Playwright 1.59.1：公开 Trace API 无暂存硬配额；10ms 监测与最终 ZIP/运行附件限额不能等同于物理暂存硬上限，不修改其内部 BufferedFS 来伪造这一保证。
