# 受控项目规格验收（F01）

日期：2026-11-18。依照 2.0 checklist 推进，复用现有私有原子文件与 beUI 交互，不引入依赖。

## 范围与产品约束

- 每个已存在、身份匹配的受管项目固定使用根目录 `spec.md`；Web 不接受本机路径，不自动读取历史 `spec/` 目录，也不创建不存在的项目。
- 读取返回项目、是否存在、Markdown 与精确内容修订。缺失可创建；旧空文件可读取修正；写入必须是有效 UTF-8、非空、无 NUL，最多 128 KiB。
- 保存必须显式确认并携带读取时的修订；在同一写锁下比较、原子替换。同内容重复保存幂等；冲突、超限、链接或坏文件均保留原文。
- 项目身份和全部祖先路径校验复用现有用例资产边界。同步与异步旧存储入口统一经过受控保存，不保留可绕过的任意写入路径。
- Web 在 Generate 中提供读取、创建、原文对照、编辑、保存与显式重新读取。修改内容或项目后清除确认；冲突保留用户输入，项目切换不能显示上个项目的迟到响应。
- 生成可明确选择使用已保存规格；未保存输入不参与执行。服务在提交时校验规格修订并冻结 Markdown/修订，作为生成与 critic 的共同输入，追加契约断言而不替换或放宽它们。
- 生成来源保存可选规格快照，并兼容没有规格的历史用例；后续规格编辑不改变已有生成来源或排队任务。

## 验证与完成条件

1. 核心：缺失、创建、读取、修改、重复保存、过期修订、未知项目、路径/符号链接/硬链接、UTF-8、空内容和大小限制，失败后原文不变。
2. 真实服务 HTTP：受控 CRUD、明确确认、冲突及错误恢复，不接受任意路径；生成 fixture 同时观测冻结规格和原契约断言。
3. Web：项目切换、原文对照、确认失效、冲突保留输入、未保存稿不能参与生成；真实浏览器验收与现有 UI/Rust 回归。
4. 同步用户指南、产品记忆和 checklist，只有以上证据齐全才勾选 F01；本地模型 fixture 不替代真实视觉业务验收。

运行时 Web 下载/升级（R03/R05）仍为独立未完成项；F01 的资产维护不依赖浏览器运行时，先推进其可验证闭环。

## 已收集证据

F01 已按上述条件验收：Rust workspace 210 项、UI 14 项、严格 TypeScript、工作台/Pages 构建、八个真实 HTTP 脚本及独立复核通过。实际 Chromium 操作覆盖创建、原文对照、修改清确认与选用、冲突保留草稿、明确 Reload、项目切换；延迟保存响应后切换另一项目，原响应不会覆盖目标编辑器。控制台 0 errors/0 warnings。生成 fixture 验证 generator/critic 和持久来源使用相同冻结规格及原契约断言，未调用真实业务模型。
