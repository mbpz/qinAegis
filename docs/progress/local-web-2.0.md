# QinAegis 2.0 开发进度

更新：2026-11-16。依据 [产品记忆](../../CONTEXT.md) 与 [批准方案](../plans/local-web.md) 分阶段推进。当前为本地服务基础开发版，未正式发布。

## 本阶段交付

| 范围 | 实现与边界 |
|---|---|
| 应用抽离 | 原 main.rs 业务移动至 app.rs / dispatch.rs；HTTP、认证与进程生命周期独立。删除 wry/tao 依赖和桌面客户端打包逻辑 |
| 本地服务 | qinaegis 默认后台启动并请求系统浏览器打开；serve/open/status/stop；仅监听 127.0.0.1；默认端口冲突后有限尝试，显式端口不静默改动；同一状态目录单实例 |
| 浏览器通信 | 同源 HTTP RPC、一次性 60 秒启动授权、8 小时闲置会话、HttpOnly/SameSite Cookie、CSRF、Host/Origin 检查、1 MiB 请求上限与有界执行；缺失静态资源真实 404 |
| 配置与报告 | 配置响应不回传两个 API 密钥；空输入保留，显式清除；校验端口、深度与模型端点；未配置 AI 仍可浏览资产；HTML 报告以无权限 iframe 隔离 |
| 契约库与治理 | 私有原子 JSON 持久化、跨进程锁、CAS、草稿/不可变发布、类型化项目绑定、纠正原因/证据/人工审核、版本比较和引用影响；导入完整验证且必须人工确认，导出不含绑定 |
| 模型注册与路由 | 独立私有注册库、密钥脱敏/保留/清除、任务角色路由、能力声明与远程数据授权；可扩展适配器工厂，当前内置 Chat Completions。生成支持有界备用链；视觉任务只支持兼容主模型 |
| 生成快照 | 任务冻结契约发布版本、项目输入、原始断言和模型候选配置；生成与 critic 共用冻结路由。跨项目保存正确，不自动发布用例；批次先校验 ID、重复和已有用例冲突 |
| 前端交互 | 按 beUI 公开免费目录复制完整源码与依赖，来源/摘要可查；统一按钮、输入、选择、勾选、多行编辑、通知、加载、文件选择、折叠与预览弹窗。业务审核与通信独立于组件层 |
| 场景基础 | 能力步骤、依赖、稳定拓扑顺序、缺失/重复/循环拒绝、重试次数上限和非幂等重试拒绝；尚无运行编排器/类型化数据流 |
| 引擎定位 | 明确安装目录清单和显式开发 sandbox；拒绝目录逃逸、越界符号链接和以源码 TS 冒充安装入口；保留 Playwright + Midscene.js |
| 任务边界 | 同时一个工作线程；取消到真实线程退出才停止，正在执行/清理时拒绝停止服务；关闭浏览器不停止服务。旧流水线初始化失败不再跳过门禁与报告阶段；引擎原始解析内容不进入日志，stderr 尾部缓存限制 64 KiB |
| 分发 | 锁定 Cargo/npm 依赖；服务归档、SHA-256 安装校验、用户目录安装与原子替换；Homebrew 单一模板；发布流程仅生成草稿，不自动公开发布 |

`runGenerate` 的任意本地规格文件路径不再经 HTTP 接受；受控项目规格资产接口属于后续范围。当前内置模型协议仍为兼容 Chat Completions；注册能力声明不等于已在线检测任意厂商或视觉引擎的实际兼容性。

## 验证证据

本机 macOS Apple Silicon：

- `cargo test --workspace --offline`：124 项通过（服务 16、core 106、集成 2）；包括契约跨项目绑定/纠正、不合法流程、运行时路径和 HTTP 会话负测。
- `cargo clippy --workspace --all-targets --offline`：退出 0。core 存在既有风格/未使用项告警，未开展无关全面整理。
- UI `npm test`：9 项通过，包括会话恢复、CSRF、人工确认参数、失败任务轮询和项目响应形状；`npm run build` 的 TypeScript 与生产构建通过。官方免费 beUI 10 个组件的记录摘要与完整源码一致；JS gzip 约 179 kB，生产构建有单包超过 500 kB 的提示，后续可按页面分包优化。
- `cargo build --bin qinaegis`（本轮机器缺失锁定依赖归档，联网补齐后构建）与 `python3 scripts/test-local-web.py /绝对路径/qinaegis`：并发后台启动、状态、进程复用、显式端口冲突、静态资源、Host/Origin/CSRF、授权重放拒绝、刷新恢复、停止及停止后非零状态通过；使用临时用户/配置/状态目录。
- `python3 scripts/test-install.py`：4 项离线归档回归通过（空格路径、坏摘要保护、符号链接拒绝、运行中保护）；正式平台归档和远程渠道尚未发布。
- `git diff --check` 通过；无新增 Rust/npm 检查错误，Clippy 既有告警保留。

真实 Chromium 浏览器使用隔离用户/状态目录，已验证项目创建及正确名称、多行 Enter 编辑、发布前人工确认、键盘选择契约版本及可读标签、类型化绑定、文件选择/完整预览/人审导入、模型注册/保存后密钥清空、任务路由和视觉备用禁用状态。预览与更新接口使用确定性响应验证 UI，不调用外部模型或更新站点。官方弹窗的焦点圈定、Escape 关闭、关闭后回到预览按钮、减少动效交互，以及通知出现/自动消失均通过；报告页使用真实项目，不再显示虚构 default。最终验收会话无浏览器错误。

新增 `scripts/test-contract-generation.py`：真实服务对接本地确定性模型，验证同一契约在两项目生成、运行期间改绑定/切路由不改变原任务、下一任务使用新路由，以及用例仍待人工审核。该脚本进入发布矩阵。

本轮未调用外部真实模型、不操作真实被测业务系统、不申请无障碍权限。真实浏览器自动打开、Playwright + Midscene.js 业务端到端执行、性能/资源目标及其他平台尚未完成验收；本地模型和领域测试不能替代这些结果。

## 后续顺序与验收缺口

1. **契约真实执行与生命周期**：现有持久化/Web 治理接入真实执行、保存历史契约快照与结果证据；补充弃用、派生及受控迁移。验收同一发布契约在两个真实项目执行。
2. **模型路由深化**：已有注册、全局任务路由和任务快照，继续补在线能力检测、项目/步骤策略、实际模型持久记录、多协议适配及视觉模型与 Midscene 版本兼容验证。
3. **运行时交付**：可复现构建执行器、锁定生产依赖、Node/浏览器版本探测与按需安装；Web 环境诊断/修复与干净机器验证。
4. **数据与任务可靠性**：配置原子写入/备份迁移、持久任务/增量日志、资源队列、可中断引擎调用/进程树回收、重启 interrupted 恢复。
5. **业务和编排闭环**：Web 创建/关联项目、规格与契约、用例编辑/审核、能力门禁、契约/模型/流程快照、真实执行和可下载报告；类型化数据流/条件/清理/授权校验。
6. **可选无障碍适配器**：先验证本机明确场景，分别检测权限/焦点/目标并提供紧急停止，随后确定发布范围。
7. **完整交付验收**：Windows 安装器、其他系统干净环境、签名、升级/回滚、自动打开、性能指标和正式发布。阶段表 P1C/P3/P4/P5/P6/P7/P8 仍有未完成项。

后续继续按已授权方案开发；不得把本文件的代码基础范围升级表述为完整 2.0 GA。
