## Findings

### 1. [explorer.ts] aiQuery result lacks schema validation

**Severity:** Medium  
**Category:** Bug  
**Confidence:** 78/100

`agent.aiQuery()` returns a generic JSON blob cast to the expected type. If the AI returns malformed data (missing fields, wrong types), the downstream `toMarkdown()` or link queue building will produce silent garbage or runtime panics.

```typescript
// Current: trusts AI response blindly
const rawInfo = await agent.aiQuery<PageInfo>(prompt, { screenshotIncluded: true });
return {
  url: pageUrl,
  title: info.title || '',           // only '' fallback for missing title
  primaryNav: Array.isArray(info.primaryNav) ? info.primaryNav : [],
  ...
};
```

**Suggested fix:** Add a validation step before building the PageInfo:

```typescript
function validatePageInfo(raw: any): PageInfo {
  return {
    url: typeof raw.url === 'string' ? raw.url : '',
    title: typeof raw.title === 'string' ? raw.title : '',
    primaryNav: Array.isArray(raw.primaryNav) ? raw.primaryNav : [],
    authRequired: raw.authRequired === true,
    links: Array.isArray(raw.links) ? raw.links : [],
    // ...etc
  };
}
```

### 2. [protocol.rs] MODEL_FAMILY hardcoded, MODEL_NAME dynamic — potential mismatch

**Severity:** Low  
**Category:** Bug  
**Confidence:** 65/100

`cfg.model` (e.g., `"MiniMax-M2.7"`) is used for both `MIDSCENE_MODEL_NAME` and `MIDSCENE_INSIGHT_MODEL_NAME`, but `MIDSCENE_MODEL_FAMILY` is hardcoded to `"qwen2.5-vl"`. If the configured model name doesn't correspond to a qwen family model, the family/name pair is inconsistent.

However, since the fix is intentional (ensure VL model family regardless of model name), and Midscene validates `MODEL_FAMILY_VALUES`, this is unlikely to cause issues in practice.

**Suggested fix:** Derive family from model name if possible, or document that `cfg.model` must be a qwen-family model:

```rust
// Example: extract "qwen3.6" from "qwen3.6-vl" model name
let model_family = cfg.model.split('-').next().unwrap_or("qwen2.5-vl");
cmd.env("MIDSCENE_MODEL_FAMILY", model_family);
```
